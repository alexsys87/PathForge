# Команды GRBL 1.1: G-коды, M-коды, $-команды и спецсимволы

Справочник по всему, что понимает прошивка **GRBL 1.1** (платы Woodpecker и другие на Arduino/ATmega328 у CNC 3018,
а также Grbl_Esp32 / MKS DLC32 и grblHAL (например, на [MKS Robin Nano V3](mks-robin-nano.md)) — с небольшими дополнениями). Для каждой команды: что делает, как записывается,
пример, на что обратить внимание и использует ли её PathForge.

Команды можно набирать в консоли вкладки **«Пульт»** (поле внизу → Enter или «Отправить»). Ответы GRBL
и расшифровку ошибок PathForge показывает в той же консоли.

## 1. Как GRBL читает программу

- **Строка = кадр.** GRBL выполняет программу построчно. Строка — не длиннее **80 символов** вместе с переводом
  строки (PathForge в формате GRBL пишет строки не длиннее 70 символов). Длинная строка → `error:11`.
- **Пробелы и регистр не важны:** `g1 x10 y5` = `G1X10Y5`.
- **Комментарии:** в круглых скобках `(так)` или после точки с запятой `; так`. GRBL их пропускает
  (PathForge при отправке убирает их сам).
- **Номер строки** `N123` допускается, но ни на что не влияет.
- **Модальность.** Большинство команд «запоминаются» до отмены другой командой той же группы: после `G1 F300`
  строка `X10` — тоже рабочий ход с подачей 300. Команды одной группы в одной строке → `error:21`.
- **Буферы.** Плата принимает в последовательный буфер 128 байт, а в планировщик — 15–16 движений вперёд
  (Grbl_Esp32 — больше). Поэтому ответ `ok` значит «строка принята в очередь», а не «выполнена»:
  станок отстаёт на десятки строк. Это важно для [продолжения программы с нужной строки](#12-что-использует-pathforge).
- **Состояние после сброса (питание, Ctrl-X):** `G0 G54 G17 G21 G90 G94 M5 M9 T0 F0 S0` — быстрые перемещения,
  система координат G54, плоскость XY, миллиметры, абсолютные координаты, подача в мм/мин, шпиндель и охлаждение
  выключены. Посмотреть текущее состояние — `$G`.

**Модальные группы GRBL 1.1**

| Группа | Команды |
|---|---|
| Движение | G0, G1, G2, G3, G38.2, G38.3, G38.4, G38.5, G80 |
| Система координат | G54, G55, G56, G57, G58, G59 |
| Плоскость | G17, G18, G19 |
| Координаты | G90, G91 |
| Центр дуги | G91.1 |
| Подача | G93, G94 |
| Единицы | G20, G21 |
| Коррекция радиуса | G40 |
| Длина инструмента | G43.1, G49 |
| Режим траектории | G61 |
| Ход программы | M0, M1, M2, M30 |
| Шпиндель | M3, M4, M5 |
| Охлаждение | M7, M8, M9 |
| Переопределения | M56 |
| Немодальные (действуют только в своей строке) | G4, G10 L2, G10 L20, G28, G30, G28.1, G30.1, G53, G92, G92.1 |

## 2. Слова строки (буквы)

| Буква | Значение | Пример |
|---|---|---|
| `G` | Подготовительная команда | `G1` |
| `M` | Вспомогательная команда (шпиндель, конец программы) | `M3` |
| `X`, `Y`, `Z` | Координаты осей (мм или дюймы) | `X10.5 Y-3` |
| `I`, `J`, `K` | Смещение центра дуги от начальной точки по X, Y, Z | `G2 X10 Y0 I5 J0` |
| `R` | Радиус дуги (вместо I/J/K) | `G2 X10 Y0 R5` |
| `F` | Подача, мм/мин (или дюйм/мин; при G93 — 1/мин) | `F300` |
| `S` | Обороты шпинделя или мощность лазера (0…`$30`) | `S1000` |
| `P` | Параметр: пауза G4 в секундах, номер системы координат в G10 | `G4 P1.5`, `G10 L20 P1` |
| `L` | Вид команды G10 | `G10 L20` |
| `T` | Номер инструмента — принимается, но смены инструмента нет | `T2` |
| `N` | Номер строки | `N10` |

## 3. G-коды

### G0 — быстрое перемещение

`G0 X… Y… Z…` — с максимальной скоростью (`$110…$112`), не по прямой гарантированно в материале не резать:
это холостой ход над заготовкой. Подача F на G0 не влияет. В лазерном режиме (`$32=1`) луч на G0 выключен.

```
G0 Z5          ; поднять инструмент
G0 X0 Y0       ; переехать в ноль
```

PathForge: все холостые ходы и подъёмы.

### G1 — рабочий ход по прямой

`G1 X… Y… Z… F…` — с подачей F. Если F ни разу не задана — `error:22`.

```
G1 Z-1 F100    ; врезаться на 1 мм с подачей 100
G1 X50 F400    ; резать до X50 с подачей 400
```

PathForge: все резы, врезания, проходы лазера (вместе с `S` — мощность на этом отрезке).

### G2 / G3 — дуга по / против часовой стрелки

Через центр: `G2 X… Y… I… J…` (I, J — смещение центра **от начала дуги**, режим G91.1 по умолчанию).
Через радиус: `G2 X… Y… R…` (R > 0 — дуга меньше 180°, R < 0 — больше). Полная окружность — только через I/J
(начало = конец). Направление смотрится сверху на плоскость (G17 — XY). Спираль: добавьте Z.

```
G0 X0 Y0
G2 X20 Y0 I10 J0 F300     ; полуокружность радиусом 10 по часовой
G3 X0 Y0 I-10 J0          ; обратно против часовой
G2 X0 Y0 I10 J0 Z-1       ; полная окружность со спуском на 1 мм (винтовое врезание)
```

GRBL разбивает дугу на отрезки с точностью `$12`. Если радиусы до начала и конца отличаются больше, чем на
0,005 мм (и на 0,1 %), — `error:33`. PathForge: выводит дуги там, где траектория идёт по окружности (настройка
«Дуги G2/G3» на вкладке «Станок»), проверяя радиус так же, как GRBL.

### G4 — пауза

`G4 P<секунды>` — подождать, движения в очереди сначала доезжают. `G4 P3` — 3 секунды.

PathForge: после `M3`, чтобы шпиндель 775 успел раскрутиться («Пауза после M3» на вкладке «Станок»).

### G10 L2 и G10 L20 — задать систему координат

- `G10 L2 P1 X… Y… Z…` — записать смещение системы координат P (1 = G54, …, 6 = G59) **от машинного нуля**.
- `G10 L20 P1 X… Y… Z…` — сделать так, чтобы **текущее положение** имело указанные координаты в системе P.
  `G10 L20 P1 X0 Y0 Z0` — «ноль здесь». `G10 L20 P1 X5.08 Y3.81` — «здесь X 5,08 Y 3,81».

Значения G54–G59 хранятся в EEPROM и переживают выключение питания. `P0` — текущая активная система.

PathForge: кнопки «X0», «Y0», «Z0», «X0 Y0», «Все», поиск Z щупом и карта высот (`G10 L20 P1 …`).
Совмещение второй стороны платы по отверстию — тоже через `G10 L20` (см. [плата фрезеровкой](pcb-milling.md)).

### G17 / G18 / G19 — плоскость дуг

G17 — XY (по умолчанию), G18 — ZX, G19 — YZ. Нужна только для дуг G2/G3. PathForge: G17.

### G20 / G21 — дюймы / миллиметры

Влияет на все координаты и подачу. PathForge: всегда G21 (мм).

### G28 / G30 и G28.1 / G30.1 — сохранённые позиции

- `G28.1` / `G30.1` — запомнить текущее **машинное** положение как позицию 1 / 2 (в EEPROM).
- `G28` / `G30` — переехать в эту позицию быстрым ходом. С осями (`G28 Z10`) — сначала в промежуточную точку
  (в текущих координатах), потом в сохранённую.

Осторожно: без концевиков и поиска дома машинные координаты после включения начинаются с того места, где стоял
станок, поэтому сохранённые позиции «переезжают». PathForge эти команды не использует.

### G38.2 … G38.5 — измерение щупом

`G38.2 Z-20 F50` — двигаться к цели, пока щуп не замкнётся; если не замкнулся — авария `ALARM:5`.
- G38.3 — то же, но без аварии, если щуп не сработал;
- G38.4 — двигаться, пока щуп **не разомкнётся** (с аварией);
- G38.5 — то же без аварии.

Результат — сообщение `[PRB:x,y,z:1]` (1 — касание было) в машинных координатах. Если щуп уже замкнут в начале —
`ALARM:4`. PathForge: «Найти Z щупом» и снятие карты высот — `G38.2`, затем `G10 L20 P1 Z<толщина пластины>`.

### G40 — отмена коррекции на радиус

Коррекции радиуса (G41/G42) в GRBL нет, G40 принимается для совместимости. Траектории с учётом радиуса фрезы
считает CAM-программа (PathForge — сама).

### G43.1 / G49 — динамическая коррекция длины инструмента

`G43.1 Z…` — сдвинуть Z на длину инструмента (вместо заново выставленного Z0 после смены фрезы), `G49` — отменить.
Только по оси Z (иначе `error:37`). PathForge вместо этого просит заново выставить Z0 на смене инструмента.

### G53 — движение в машинных координатах

`G53 G0 Z-1` — только в этой строке координаты машинные (от «дома»), только с G0/G1 (иначе `error:30`).
Удобно для подъёма к верхнему концевику: `G53 G0 Z-1`.

### G54 … G59 — выбор системы координат

Шесть рабочих нулей (например, две заготовки на столе). По умолчанию G54. Смещения задаются G10 и показываются
командой `$#`. PathForge: G54.

### G61 — точный останов в углах

Режим «точной траектории» — единственный, который есть в GRBL (G61.1, G64 не поддерживаются).
Скорость в углах определяется `$11` (junction deviation).

### G80 — отмена режима движения

После G80 строка с координатами без G-команды — ошибка `error:31`.

### G90 / G91 — абсолютные / относительные координаты

G90 — координаты от нуля (по умолчанию). G91 — от текущего положения (каждое `X1` сдвигает на 1 мм).
PathForge: G90 в программах; перемещения кнопками — через `$J=G91 …`.

### G91.1 — центр дуги I/J/K относительно начала

Режим по умолчанию и единственный в GRBL (G90.1 не поддерживается).

### G92 / G92.1 — временный сдвиг координат

`G92 X0 Y0` — «здесь ноль», но **не** записывается в EEPROM и складывается с G54. `G92.1` — сбросить.
Легко запутаться: если после G92 выключить питание, сдвиг пропадёт. Используйте лучше `G10 L20`.
Продолжение программы с нужной строки предупреждает, если в программе встречается G92.

### G93 / G94 — режим подачи

G94 — подача в мм/мин (по умолчанию). G93 — «обратное время»: F = 1/минуты на кадр (для поворотных осей; на 3018
не нужно). PathForge: G94.

## 4. M-коды

| Команда | Что делает | Заметки |
|---|---|---|
| `M0` | Пауза программы (как «Пауза» на пульте). Продолжить — `~` (cycle start) | PathForge **не отправляет** M0: на этой строке он сам останавливает отправку и ждёт «Продолжить» — так можно двигать станок и заново найти Z при смене инструмента |
| `M1` | Необязательная пауза | GRBL принимает и **пропускает** |
| `M2`, `M30` | Конец программы: сброс в G54 G17 G90 G94, M5, M9 и т. п., сообщение `[MSG:Pgm End]` | PathForge пишет `M30` в конце |
| `M3 S…` | Шпиндель по часовой стрелке / лазер с постоянной мощностью | В лазерном режиме луч горит только во время G1/G2/G3 |
| `M4 S…` | Шпиндель против часовой / лазер с **динамической** мощностью | В лазерном режиме (`$32=1`) мощность падает пропорционально скорости на разгоне и в углах — нет пережога. PathForge для лазера пишет `M4 S0` и мощность словом `S` в каждом рабочем ходе |
| `M5` | Шпиндель / лазер выключить | |
| `M7` | Охлаждение туманом (mist) | Только если прошивка собрана с этой опцией |
| `M8` | Охлаждение СОЖ (flood) — выход coolant | На 3018 обычно не подключён; иногда этим выходом включают обдув лазера |
| `M9` | Охлаждение выключить | |
| `M56 P…` | Управление парковкой при открытии двери | Только в сборках с этой опцией |

`S` — значение от `$31` до `$30`. При `$30=1000` (профили 3018 в PathForge) `S1000` — максимум оборотов или
100 % мощности лазера, `S300` — 30 %.

## 5. Команды $ (системные)

Работают только в состоянии **Idle** (иначе `error:8`), кроме `$J=`, который можно и во время другого
перемещения кнопками. В программу G-code их вставлять нельзя (PathForge предупредит).

| Команда | Что делает |
|---|---|
| `$` | Справка: список команд `[HLP:$$ $# $G $I $N $x=val $Nx=line $J=line $SLP $C $X $H ~ ! ? ctrl-x]` |
| `$$` | Все настройки `$0…$132` с текущими значениями ([раздел 7](#7-настройки-0132)) |
| `$x=значение` | Изменить настройку: `$32=1`. Сохраняется в EEPROM сразу |
| `$#` | Параметры координат: `[G54:…]`…`[G59:…]`, `[G28:…]`, `[G30:…]`, `[G92:…]`, `[TLO:…]` (длина инструмента), `[PRB:…]` (последнее касание щупа) |
| `$G` | Текущие модальные режимы: `[GC:G0 G54 G17 G21 G90 G94 M5 M9 T0 F0 S0]` |
| `$I` | Версия и опции сборки: `[VER:1.1h.20190825:]`, `[OPT:V,15,128]` (буквы опций, размер планировщика, буфера) |
| `$N` | Стартовые строки `$N0=`, `$N1=` — выполняются после каждого включения и сброса |
| `$N0=G21 G90` | Записать стартовую строку (пустая `$N0=` — стереть). Осторожно с движениями в стартовых строках |
| `$C` | Режим проверки G-code: GRBL разбирает строки, но ничего не двигает и не включает. Повторный `$C` — выход (с перезапуском). PathForge: кнопка **«Проверить ($C)»** |
| `$X` | Снять блокировку после аварии (без поиска дома). PathForge: **«Разблокировать»** |
| `$H` | Поиск дома по концевикам (нужно `$22=1`). PathForge: **«Домой»** |
| `$J=…` | Перемещение кнопками (jog): `$J=G91 X10 F1000` — на 10 мм вправо; `$J=G53 X0 Y0 F2000` — в машинные координаты. Нужны координаты и F. Не меняет модальное состояние программы, отменяется символом `0x85`. С мягкими пределами цель за полем → `error:15`. PathForge: кнопки, клавиатура и джойстик |
| `$RST=$` | Сбросить настройки `$` к заводским значениям прошивки |
| `$RST=#` | Сбросить G54–G59, G28, G30 |
| `$RST=*` | Сбросить всё (настройки, координаты, стартовые строки) |
| `$SLP` | Режим сна: выключить шпиндель и моторы; выход — только сбросом |

Grbl_Esp32 / MKS DLC32 добавляют свои команды (`$Sta/SSID=`, `[ESP…]` и др.) — см.
[инструкцию по MKS DLC32](mks-dlc32.md).

## 6. Спецсимволы реального времени

Однобайтовые команды, которые GRBL выполняет **сразу**, не дожидаясь очереди строк и без перевода строки.
Печатные (`?`, `!`, `~`) можно набрать в консоли; остальные PathForge отправляет кнопками.

| Байт | Символ | Что делает | В PathForge |
|---|---|---|---|
| `0x18` | Ctrl-X | **Мягкий сброс:** немедленная остановка, очистка буферов. Если станок двигался — `ALARM:3` (положение могло сбиться) | «Сброс», «Стоп» (после плавной остановки) |
| `0x3F` | `?` | Отчёт о состоянии `<…>` | 5 раз в секунду, автоматически |
| `0x7E` | `~` | Пуск / продолжение после паузы (cycle start) | «Продолжить» |
| `0x21` | `!` | Пауза с плавным торможением (feed hold), положение сохраняется | «Пауза», первая половина «Стопа» |
| `0x84` | — | Открыть «дверь безопасности» (как кнопка Door) | — |
| `0x85` | — | Отменить перемещение кнопками (jog cancel) | Отпускание клавиши, ■ |
| `0x90` | — | Подача 100 % | «100 %» |
| `0x91` / `0x92` | — | Подача +10 % / −10 % (пределы 10…200 %) | «+10 %» / «−10 %» |
| `0x93` / `0x94` | — | Подача +1 % / −1 % | — |
| `0x95` / `0x96` / `0x97` | — | Быстрые перемещения 100 % / 50 % / 25 % | — |
| `0x99` | — | Шпиндель 100 % | «100 %» |
| `0x9A` / `0x9B` | — | Шпиндель +10 % / −10 % (10…200 %) | «+10 %» / «−10 %» |
| `0x9C` / `0x9D` | — | Шпиндель +1 % / −1 % | — |
| `0x9E` | — | Остановить / запустить шпиндель (только в паузе) | — |
| `0xA0` | — | Переключить охлаждение M8 | — |
| `0xA1` | — | Переключить охлаждение M7 (если есть) | — |

## 7. Настройки $0…$132

Посмотреть — `$$`, изменить — `$номер=значение`. В скобках — значения по умолчанию прошивки; у плат 3018
производитель обычно уже записал свои.

| № | Что | Пояснение и типичное значение для 3018 |
|---|---|---|
| `$0` | Длительность импульса шага, мкс (10) | Не трогать. Минимум 3 (`error:6`) |
| `$1` | Задержка отключения моторов, мс (25) | `255` — моторы держат всегда (ось Z не проседает под весом шпинделя) |
| `$2` | Инверсия импульса шага, маска | 0 |
| `$3` | Инверсия направления осей, маска (X=1, Y=2, Z=4) | Подбирается так, чтобы X+ — вправо, Y+ — от себя (стол на вас), Z+ — вверх. Например, `$3=5` — перевернуть X и Z |
| `$4` | Инверсия сигнала включения драйверов | 0 |
| `$5` | Инверсия концевиков | 0 или 1 — смотря какие концевики (нормально разомкнутые / замкнутые) |
| `$6` | Инверсия щупа | 0. Если состояние щупа «замкнут» без касания — 1 |
| `$10` | Что в отчёте о состоянии (маска): 1 — машинные координаты MPos (иначе WPos), 2 — заполненность буферов `Bf` | 1 или 3 (PathForge понимает и MPos, и WPos; с `Bf` точнее подсвечивает выполняемую строку) |
| `$11` | Junction deviation, мм (0,010) | Насколько можно «срезать» угол на скорости. Больше — быстрее в углах, но грубее |
| `$12` | Точность дуг, мм (0,002) | На сколько отрезки дуги отклоняются от окружности |
| `$13` | Отчёты в дюймах (0) | **0** — PathForge рассчитывает на миллиметры |
| `$20` | Мягкие пределы (0) | 1 — GRBL не пустит за `$130…$132`. Требует поиска дома (`$22=1`), иначе `error:10` |
| `$21` | Жёсткие пределы — концевики останавливают станок (0) | 1, если есть концевики |
| `$22` | Поиск дома $H (0) | 1, если есть концевики |
| `$23` | Направление поиска дома, маска | Зависит от расположения концевиков |
| `$24` | Подача поиска дома (точная), мм/мин (25) | 25–100 |
| `$25` | Подача поиска дома (быстрая), мм/мин (500) | 500–1000 |
| `$26` | Антидребезг концевиков, мс (250) | 25–250 |
| `$27` | Отъезд от концевика после поиска, мм (1) | 1–3 |
| `$30` | Максимальные обороты = значение S при максимуме (1000) | **1000** — профили 3018 в PathForge пишут S0…S1000 |
| `$31` | Минимальные обороты (0) | 0 |
| `$32` | **Лазерный режим** (0) | **1** — для лазера (луч гаснет на G0, мощность M4 следует за скоростью, нет остановок на смене S). **0** — для шпинделя, иначе он будет останавливаться на холостых ходах |
| `$100`, `$101`, `$102` | Шагов на мм по X, Y, Z (250) | Часто 800 у штатного 3018, но зависит от винтов и микрошага — проверьте измерением (см. первый запуск) |
| `$110`, `$111`, `$112` | Максимальная скорость, мм/мин (500) | Около 1000 для X/Y и 500–600 для Z у штатного 3018. Не повышайте без нужды |
| `$120`, `$121`, `$122` | Ускорение, мм/с² (10) | Заводские. Меньше — плавнее, меньше пропусков шагов |
| `$130`, `$131`, `$132` | Рабочий ход, мм (200) | 300, 180, 45 у 3018 — для мягких пределов |

Grbl_Esp32 / FluidNC используют другие имена настроек (или YAML-конфиг) — см. их документацию и
[инструкцию по MKS DLC32](mks-dlc32.md).

## 8. Ответы GRBL: ok, ошибки, отчёт о состоянии, сообщения

**На каждую строку** GRBL отвечает ровно одним: `ok` или `error:N`. На этом построена потоковая отправка:
PathForge (как Candle) считает байты в 128-байтовом буфере платы и подаёт новые строки по мере ответов.

**Приветствие** после включения или сброса: `Grbl 1.1h ['$' for help]`.

**Отчёт о состоянии** (ответ на `?`):

```
<Run|MPos:10.000,20.000,-1.000|Bf:12,100|FS:400,10000|WCO:2.000,3.000,-5.000|Ov:120,100,90|Pn:PZ|A:S>
```

| Поле | Значение |
|---|---|
| Первое слово | Состояние: `Idle` (готов), `Run` (работа), `Hold:0` (пауза завершена) / `Hold:1` (тормозит), `Jog` (перемещение кнопками), `Alarm` (авария), `Door:0…3` (дверь), `Check` (режим $C), `Home` (поиск дома), `Sleep` |
| `MPos` / `WPos` | Машинные / рабочие координаты. Рабочие = машинные − `WCO` |
| `WCO` | Смещение рабочего нуля (G54 + G92 + G43.1); приходит не в каждом отчёте |
| `Bf` | Свободно мест в планировщике и байт в последовательном буфере |
| `FS` (или `F`) | Текущая подача и обороты |
| `Ov` | Переопределения подачи, быстрых, шпинделя, % |
| `Pn` | Сработавшие входы: `X`, `Y`, `Z` — концевики, `P` — щуп, `D` — дверь, `H` — пауза, `R` — сброс, `S` — пуск |
| `A` | Включено: `S` — шпиндель по часовой, `C` — против, `F` — СОЖ, `M` — туман |
| `Ln` | Номер выполняемой строки N (если прошивка собрана с этой опцией) |

**Сообщения в квадратных скобках:**

| Сообщение | Когда |
|---|---|
| `[MSG:'$H'\|'$X' to unlock]` | После включения/сброса при включённом поиске дома или после аварии |
| `[MSG:Caution: Unlocked]` | После `$X` |
| `[MSG:Enabled]` / `[MSG:Disabled]` | Вход / выход из режима `$C` |
| `[MSG:Check Door]` | Открыта дверь |
| `[MSG:Check Limits]` | При старте замкнут концевик |
| `[MSG:Pgm End]` | Выполнен M2/M30 |
| `[MSG:Reset to continue]` | После аварии, требующей сброса |
| `[MSG:Sleeping]` | После `$SLP` |
| `[GC:…]` | Ответ на `$G` |
| `[G54:…]`, `[PRB:x,y,z:1]` … | Ответ на `$#`, результат щупа |
| `[VER:…]`, `[OPT:…]` | Ответ на `$I` |
| `[HLP:…]` | Ответ на `$` |
| `[echo:…]` | Эхо строки (только в отладочных сборках) |

## 9. Коды ошибок (error:N)

Ошибка значит: **эта строка не выполнена**. Строки, уже принятые раньше, продолжают выполняться. PathForge при
ошибке во время программы ставит станок на паузу и спрашивает: «Продолжить» (пропустить строку) или «Стоп».

| Код | Что значит | Что делать |
|---|---|---|
| 1 | В строке есть слово без буквы | Опечатка в программе |
| 2 | Неверное или пропущенное число | Например, `X` без числа или `X1.2.3` |
| 3 | Неизвестная команда `$` | Проверьте написание |
| 4 | Отрицательное значение там, где нужно положительное | Например, `F-100` |
| 5 | Поиск дома (`$H`) выключен (`$22=0`) | Включите `$22=1`, если есть концевики |
| 6 | Импульс шага меньше 3 мкс | `$0` не меньше 3 |
| 7 | Ошибка чтения EEPROM, настройки сброшены | Проверьте и запишите настройки заново |
| 8 | Команда `$` доступна только в Idle | Дождитесь остановки |
| 9 | G-code заблокирован: авария или перемещение кнопками | `$X` (разблокировать) или дождаться конца перемещения |
| 10 | Мягкие пределы без поиска дома | Сначала `$22=1` |
| 11 | Строка длиннее 80 символов | Разбейте строку; PathForge в формате GRBL пишет до 70 |
| 12 | Значение настройки превышает максимальную частоту шагов | Слишком большие `$11x` при данных `$10x` |
| 13 | Открыта дверь безопасности | Закройте дверь / проверьте вход Door |
| 14 | Строка не помещается в EEPROM (`$N`) | Короче стартовая строка |
| 15 | Перемещение кнопками за пределы поля | Мягкие пределы: цель за `$13x` |
| 16 | Неверная команда `$J=` | Нужны координаты и F, нельзя другие G-коды |
| 17 | Лазерный режим требует ШИМ-выхода | Прошивка/плата без ШИМ на шпинделе |
| 20 | Неподдерживаемая команда G-code | Например, `M6`, `G41`, `G81`. Выберите формат **GRBL** на вкладке «Станок» |
| 21 | Две команды одной модальной группы в строке | Например, `G0 G1` |
| 22 | Не задана подача F | Добавьте `F` до первого `G1` |
| 23 | Команде нужно целое число | Например, `G10 L2.5` |
| 24 | Две команды в строке требуют осей | Например, `G10` и `G0` в одной строке |
| 25 | Слово повторяется в строке | `X1 X2` |
| 26 | Команде нужны оси, а их нет | Например, `G2` без координат |
| 27 | Номер строки N вне диапазона | N до 9 999 999 |
| 28 | Не хватает слова P или L | `G10` без `L`, `G4` без `P` |
| 29 | Поддерживаются только G54–G59 | `G59.1` и т. п. нет |
| 30 | G53 только с G0 или G1 | |
| 31 | Лишние оси при отменённом движении (G80) | |
| 32 | У дуги нет координат в выбранной плоскости | Проверьте G17/G18/G19 |
| 33 | Недопустимая цель: дуга невозможна (радиусы не сходятся) или щуп уже в цели | Пересчитайте программу; для щупа — поднимите инструмент |
| 34 | Ошибка расчёта дуги через R | Используйте I/J |
| 35 | У дуги нет I/J/K | |
| 36 | В строке остались неиспользованные слова | Например, `G0 X1 F100 P5` |
| 37 | G43.1 применяется только к оси Z | |
| 38 | Номер инструмента слишком большой | T больше 255 |

## 10. Коды аварий (ALARM:N)

Авария блокирует станок: G-code не выполняется (`error:9`) до `$X` (разблокировать) или `$H` (поиск дома).
Положение после аварий 1, 3, 6–10 могло сбиться — проверьте ноль.

| Код | Что значит | Что делать |
|---|---|---|
| 1 | Сработал концевик (жёсткий предел) | Отъехать с концевика, `$X`, найти дом или выставить ноль заново |
| 2 | Цель за пределами поля (мягкие пределы), движение не начато, положение сохранено | Программа больше поля или ноль выставлен не там |
| 3 | Сброс во время движения | Проверить ноль: шаги могли потеряться |
| 4 | Щуп замкнут ещё до начала измерения | Зажим на фрезе касается пластины / провода замкнуты / нужна инверсия `$6` |
| 5 | Щуп не коснулся на заданном ходе | Опустите инструмент ближе или увеличьте «Ход вниз»; проверьте провода |
| 6 | Поиск дома прерван сбросом | Повторить `$H` |
| 7 | Поиск дома прерван: открыта дверь | |
| 8 | Поиск дома: концевик не отпустился при отъезде | Увеличить `$27` |
| 9 | Поиск дома: концевик не найден | Проверить концевики, `$23`, ход `$13x` |
| 10 | Поиск дома: не найден второй концевик оси (в сборках с двумя моторами на оси) | |

## 11. Что не поддерживается

GRBL — упрощённый интерпретатор. В нём **нет**:

- коррекции радиуса `G41`/`G42` (считает CAM);
- циклов сверления `G81…G89` (PathForge пишет сверление обычными G0/G1, с выводом стружки — по шагам);
- смены инструмента `M6` (ошибка 20) — PathForge в формате GRBL вместо неё ставит паузу `M0` с комментарием;
- `G43` с таблицей инструментов (только `G43.1`), `G64`, `G90.1`, `G59.1…`, переменных и подпрограмм (`#1`, `O100`, `M98`);
- 4-й оси (в стандартной прошивке для ATmega328).

## 12. Что использует PathForge

| Где | Команды |
|---|---|
| Программа (формат GRBL) | `G90 G21 G17 G94`, `G0`, `G1`, `G2`/`G3` (если включены дуги), `G4` (пауза шпинделя), `M3 S…`/`M5` (шпиндель), `M4 S0` + `S` в каждом ходе (лазер), `M0` (смена инструмента — обрабатывается отправителем), `M30` |
| Ноль | `G10 L20 P1 X0`, `… Y0`, `… Z0`, `… X0 Y0 Z0`; переезд в ноль — `G0 Z<безопасная>` и `G0 X0 Y0` |
| Щуп и карта высот | `G38.2 Z… F…`, `G10 L20 P1 Z…`, `G0` |
| Перемещение кнопками, клавиатурой, джойстиком | `$J=G91 G21 X… F…`, отмена — `0x85` |
| Кнопки | `$X` (разблокировать), `$H` (домой), `$C` (проверить программу), `~`, `!`, `Ctrl-X`, переопределения `0x90…0x92`, `0x99…0x9B` |
| Опрос | `?` пять раз в секунду; ответы `ok`/`error:N`/`ALARM:N` расшифровываются в консоли |
| Продолжение со строки | Перед продолжением: `G21 G90 G94 G17 G54`, `G0 Z<безопасная>`, `G0 X… Y…`, `M3 S…` + `G4 P…`, `G0 Z<чуть выше>`, `G1 Z… F<врезание>`, `F<подача>`, затем строки программы |

**Продолжение программы с нужной строки** («Пульт» → «Со строки» → «▶ С этой строки»). GRBL отвечает `ok`, когда
строка попала в очередь, а станок отстаёт на 15–16 движений. Поэтому после остановки PathForge подставляет номер
примерно на 20 строк раньше последней принятой: несколько движений повторятся «по воздуху» — это безопасно, а
пропустить кусок — нет. После пропадания питания машинные координаты без поиска дома теряются, хотя G54 хранится
в EEPROM: выставьте ноль X/Y/Z **заново точно в той же точке**, иначе продолжение будет смещено.
